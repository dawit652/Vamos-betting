### Facts measured in this session

- **Catalogue size.** The first catalogue (515 selections) listed only 437–477 options after pruning; with task 2.8 (673 selections) the four reference matches list **635** (balanced, 1.45 v 1.15), **629** (away favourite), **596** (heavy home favourite) and **587** (low-scoring). The prototype measured 503–541 for its own catalogue.
- **Speed.** About 26 ms to price all 194 markets of one match on one core, with no grid trimming (Hulusport's board of 1,100 matches would take about 30 seconds).
- **Draw correction sign.** In the standard Dixon–Coles form used here (τ00 = 1 − λh·λa·ρ, τ11 = 1 − ρ), a **negative** ρ raises 0-0 and 1-1. Fitted values are usually about −0.1 to −0.2. Keep this in mind for the fit (P-4).
- **Equivalence.** Pricing today's nine market types through the rule table reproduces today's odds exactly. The non-void mass is summed in the same order as today's code, so whole-line Asian handicap and draw-no-bet prices do not move.

## 5. Known issues found in this session

- **A flaky test, fixed.** `packages/db/test/payments-smsrail.test.ts` ("never credits someone else's unmatched payment to the paster") failed about once in 50 runs: the thief's deposit took a random 1–50 santim offset, and an offset of 3 gave it the victim's exact amount while it was opened before the SMS's time, which by the rail's own rule is a genuine match. The test now pins the offset; the payment code was right and is unchanged.
- **`pnpm lint` fails in a fresh checkout** on `apps/web` pages (unresolved types of `params` and `searchParams`): Next.js's generated route types are missing until the web app is built. Not caused by this work; every changed file lints clean.
- **Truth-check scope.** Disabled sources are included, so switching a source off does not erase its record; restrict to enabled sources if the owner prefers.
