## 1. Before the first task

1. Check out `claude/fervent-bardeen-axglt2`, run `pnpm install`, `pnpm services:start`, then `OPERATING_MODE=demo pnpm db:migrate`. Run tests with `OPERATING_MODE=demo` (the default mode is licensed and refuses the mock payment provider).
2. **API keys are not in the repository.** They were saved as network secrets of the previous account's cloud environment and do not travel with the code. In the new environment, save them again the same way (the `request_credential` tool, or the environment's settings), never in a file or a variable:
   - API-Football (Pro, active until 13 Dec 2026): host `v3.football.api-sports.io`, header `x-apisports-key`. **In the third session's environment a secret exists but the provider rejects it** ("Missing application key"): it is probably saved for `Authorization: Bearer`; it must be the header `x-apisports-key`.
   - The Odds API (20K plan today; the owner moves to the 100K plan next week, which may bring a new key): host `api.the-odds-api.com`, header `x-api-key`.
3. **Credits are shared with production.** The Odds API key was already at 3,968 of 20,000 credits on 13 Nov, so the production scraper uses it. Use only the free endpoints (`/v4/sports`, `/v4/sports/{key}/events`; check `x-requests-last: 0`) unless the owner agrees. On the 20K plan the credit guard trips at about 1,500 credits a day: run at most 8 to 10 big leagues, without the handicap market, until the 100K plan.
4. Every switch added by this work is **off by default**: `SCRAPER_PRICE_EXPIRY_MINUTES=0`, `SCRAPER_FACTORY_MARKETS=off`, `FEATURE_FACTORY_MARKETS=false`, `OWNER_ALERT_PHONES` empty, the per-competition `factory_markets` flag false, the events-mode Odds API source a disabled draft. Keep it that way in code; switching on is the owner's call.
