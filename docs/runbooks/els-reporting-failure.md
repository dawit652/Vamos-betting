# ELS reporting failure

The worker writes every reportable event exactly once into the ELS directory (`ELS_REPORT_DIR`, the `els`
volume at `/var/lib/vamos/els`): `stream/<date>.jsonl` and `daily/<date>.csv`. Folders are `0700`, files
`0600`, owned by the container user `node` (uid 1000). The durable `els_reports` table records each outbox id
and the hash of its line; a sweep re-emits rows that were not written. Details:
[compliance.md](../compliance.md#21-els-transaction-stream).

**Severity:** SEV2. Gaps in the regulator stream can breach the licence; start the clock on any
notification duty your licence sets (**to confirm**; ELS has not published its reporting interface).

## Detect

- Back office -> Compliance (daily summaries) shows the ELS reporter status; the API serves it as
  `GET /admin/compliance/els`: reporter and mode, records written for the last 14 business dates, every
  pending record, the **oldest pending event** and the **last error**. Pending that does not drain within a few
  minutes is a failure; "oldest pending" tells you how long the stream has been behind.
- Alerts: pending count/age, `worker` unhealthy (`curl localhost:4100/ready` -> queues), disk space on the
  Docker host, `docker compose logs worker | grep -i els`.

## Diagnose

| Last error / symptom                                   | Cause                                                                                  | Fix                                                                                                                                                                                                    |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `EACCES` / permission denied                           | Directory owned by root or another uid (a bind mount or a restored archive)            | `docker compose exec -u root worker chown -R node:node /var/lib/vamos/els` and `chmod 700` on directories, `600` on files                                                                              |
| `ENOSPC` / no space left                               | Disk full                                                                              | Free space (old backups, logs, WAL volume), then the sweep drains the pending records                                                                                                                  |
| Mode is `off` or `http`; status says placeholder       | Misconfiguration (`off` is demo only; `http` sends nothing until ELS publishes a spec) | Set `ELS_REPORTING_MODE=file`, restart api and worker. Licensed mode refuses anything else                                                                                                             |
| Status "directory not found" on the api                | The api sees another path/volume than the worker                                       | Both must mount the same `els` volume (api read-only) with the same `ELS_REPORT_DIR`                                                                                                                   |
| Pending grows, no error, worker unhealthy              | Worker down, Redis down, or the `els` queue stuck                                      | `docker compose ps`; restart `redis` then `worker`; the dispatcher and sweeps recreate the jobs from the outbox                                                                                        |
| Files missing or truncated, `els_reports` says written | Volume lost/restored from an older copy, or manual deletion                            | Restore the ELS archive ([restore](restore-from-backup.md)); lines written after that backup must be regenerated by engineering from `els_reports` + the outbox (the stored hash lets you verify them) |

## Recover

1. Fix the cause; do not stop the worker for long, the backlog only grows (it is safe: the outbox keeps
   everything).
2. Watch pending drop to 0 and "written" counts per business date match the ledger/bet counts of those days.
   The sweep's cursor trails by 10 minutes on purpose, so the newest events may take that long.
3. Never edit `.jsonl`/`.csv` by hand and never copy files between environments: a line is evidence. If a
   line is wrong, engineering fixes the cause; corrections are new records (e.g. `bet.reopened`).
4. Make an archive now: `infra/scripts/backup.sh els`, and confirm the next scheduled backup includes the
   directory.
5. Record the gap (from, to, cause, records re-emitted) and hand it to the licence holder for the regulator.
   Final daily summaries are immutable; a late record is reported as a correction on the day it is posted.

## Prevention

Alert on disk below 20% and on pending age above 15 minutes; mount the `els` volume on durable storage;
include it in every backup and the restore drill ([backups](../backups.md)); keep 7 years.
